# Plan: Go→Rust big-bang migration

## Outcome
- result: `zbrain` is rewritten from Go (32.3k LOC, 331 tests) to Rust as a big-bang migration on a long-lived `rust-rewrite` branch. At cutover, a single PR replaces the Go tree, CI, Makefile, and docs authority with a Rust workspace whose behavior is verified identical to the frozen Go binary via a living-oracle parity strategy.
- success_signals:
  - Golden-fixture parity: Rust output is byte-identical to the Go oracle on deterministic fields (ask/doctor/status JSON, digests, claim/evidence file trees, source.yaml).
  - Differential CLI harness runs both binaries against the same isolated `ZBRAIN_HOME` fixture set and diffs schema-level JSON; green for every command surface before cutover.
  - 1:1 test port for trust-critical modules: lifecycle, trust_validation, challenge/approval, evidence immutability, workspace isolation.
  - p95@100K ask latency ≤ Go baseline (`docs/proofs/bench-baseline-full.json`).
  - FTS5 confirmed available in the bundled rusqlite build (compile-time assert + smoke).
  - Full Rust gate green at cutover: `cargo test --workspace`, `cargo clippy -- -D warnings`, `cargo build --release`, `make smoke` (isolated ZBRAIN_HOME, rc=0), `git diff --check`.
  - `git revert` of the cutover commit restores the Go tree and gate intact.

## Authority and Requirements
- authority:
  - Owner decision 2026-09-04: migrate Go→Rust, big-bang strategy, drivers = perf + single static binary + owning a Rust codebase + embeddability ("tất cả").
  - Owner decision 2026-09-04: the AGENTS.md "Go-native CLI" constraint is superseded at cutover (M8); it remains in force on `master` until the cutover PR merges.
  - `trusted-memory-spec.md` and `docs/trusted-agent-gateway-spec.md` define behavior contracts that do not change with the language.
  - Exploration evidence 2026-09-04: embedder is a pure in-process token embedder (no HTTP sidecar, `internal/runtime/embedder.go`); concurrency surface is 3 files only (coordination, embedder, mcp safeWriter); MCP tests drive in-memory transports; workspace flock is plain `flock(2)` (`internal/runtime/coordination.go`).
- requirements:
  - R1 [accepted]: Cutover is one PR that deletes the Go tree and switches CI to the Rust toolchain (`cargo test --workspace`, `cargo clippy -D warnings`, `cargo build --release`, `make smoke`, `CGO` concept removed); `git diff --check` stays clean. | source: owner big-bang decision
  - R2 [accepted]: Data formats are frozen bit-for-bit: OKF Markdown claims, evidence `raw`+`source.yaml` (0400), index SQLite schema, file modes (dirs 0700, canonical md 0600, evidence 0400, derived 0600).   - R3 [accepted]: Golden fixtures generated by the Go oracle from a shared fixture set gate every milestone that touches canonical or trusted-output behavior. | source: big-bang risk mitigation
  - R4 [accepted]: Differential CLI harness compares Go vs Rust binary output on the same `ZBRAIN_HOME` fixture; runs as a CI job on `rust-rewrite` from M2 onward. | source: drift risk mitigation
  - R5 [accepted]: SQLite stack is `rusqlite` with `bundled` feature; first M4 task asserts FTS5 availability at compile/run time; p95@100K bench must be ≤ Go baseline. | source: owner stack choice; perf driver
  - R6 [accepted]: MCP gateway is hand-rolled JSON-RPC over stdio (serde_json), preserving the current protocol revisions and behaviors: legacy handshake, stateless `server/discover`, per-request `_meta`, `isError` for schema-invalid input, `-32602` oversized/unknown, `-32603` server faults; testable over in-memory transports via IO traits. | source: internal/mcp current behavior; rmcp rejected (custom protocol surface)

## Non-goals
- NG1: Behavior redesign or new features during migration; port behavior as-is (refactor only where Go cannot translate).
- NG2: Remote/HTTP MCP transport, REST, connectors, network fetch — unchanged non-goals of the product.
- NG3: Data format changes, schema migrations, or new file layouts.
- NG4: Windows cross-compile targets; CI stays ubuntu + macOS.
- NG5: tokio/async anywhere in the workspace.
- NG6: Deleting or degrading the Go tree before the cutover gate passes.
- NG7: Replacing the token-loopback embedding algorithm with a different model.

## Approach and Risks
- approach: Cargo workspace `crates/zbrain` (bin crate; internal modules mirror `internal/runtime` package split) on branch `rust-rewrite`. The Go tree stays on `master` as a frozen living oracle: a fixture generator (`crates/tools/fixture-gen`, a small Go program reusing `internal/runtime`) renders deterministic fixtures (ask/doctor/status JSON, digests, file trees, source.yaml) from a shared fixture workspace into `crates/zbrain/tests/fixtures/`; every phase gates on those golden files plus a differential CLI harness (`scripts/parity.sh` runs Go and Rust binaries against the same isolated `ZBRAIN_HOME` and diffs schema-level JSON with tolerant timestamps/IDs). Phase order follows real dependency: foundation (paths/perms/flock) → assets/setup → claims+evidence → lifecycle+trust+lint → index+query+embed → MCP → approval/campaign → CLI/view/eval → cutover. Dependencies ≤ 10 crates: serde, serde_json, serde_yml, rusqlite (bundled), include_dir, console, chrono, libc. No async runtime; std threads only (view server, safeWriter mutex).
- constraints:
  - Behavior ported as-is; no redesign, no format changes (R2).
  - `master` untouched except Go-side critical fixes; all work on `rust-rewrite` (R9).
  - Fixture generation is Go-oracle-owned; Rust tests must not hand-maintain parallel expectations.
  - Story/phase definitions below are immutable once written.
- execution_map_parallel_rounds:
  - "R1 (1 agent): m0-foundation — serial by design; everything below reads its paths/flock/fixtures."
  - "R2 (3 agents): m1-assets-setup ∥ m2-claims-evidence ∥ m5-mcp-gateway W1 (transport/framing/revisions only)."
  - "R3 (2 agents): m3-lifecycle-trust ∥ m5-mcp-gateway W2.T1 (claim resource + evidence_capture, gated on m2 from R2)."
  - "R4 (2 agents): m4-index-query ∥ m6-approval-campaign (both gated on m3 from R3)."
  - "R5 (3 agents): m5 W2.T2+W2.T3 (remaining tools + real-client smoke) ∥ m7 W2.T1 view (gated on m2) ∥ m7 W1.T1 CLI framework (gated on m0)."
  - "R6 (1 agent): m7 full wiring — CLI surface completion + eval suite + smoke + parity all (gated on m4/m5/m6)."
  - "R7 (1 agent): m8-cutover — serial, single PR, owner sign-off."
  - "Max concurrency 3; core data track (m0→m2→m3→m4) is inherently serial. Subagents coordinate via the `rust-rewrite` branch with one merge per phase (work stage runs per-phase; check gates between rounds)."
- risks:
  - FTS5 not enabled in libsqlite3-sys `bundled` build. Mitigation: first M4 task is a compile+run assertion; fallback path is enabling `SQLITE_ENABLE_FTS5` via the bundled feature's compile opts or vendored build config. If neither works, phase stops (premise collapse — index behavior is the product).
  - Hand-rolled MCP drifts from real clients. Mitigation: port the full MCP conformance test set (mcp_test.go, campaign_test.go transports) and run a real Claude/Codex stdio smoke before M6 sign-off.
  - Oracle drift over 6–8 weeks (Go frozen but critical fixes may cherry-pick). Mitigation: differential harness runs in CI on every `rust-rewrite` PR; fixture regeneration is part of any Go-side cherry-pick.
  - Ownership-model rewrites balloon scope. Mitigation: translate data flow first (owned values read from disk); `Arc/RwLock` only where the Go mutex surface is (coordination, safeWriter, embedder).
  - Golden-fixture byte drift (YAML emitter ordering, float formatting). Mitigation: fixture comparison normalizes only timestamps/IDs; everything else byte-compared; serde_yml two-column block style configured to match yaml.v3 output order.
  - Cutover breaks consumers (skills, engine assets referencing Go commands). Mitigation: M8 includes a repo-wide grep for Go-specific references; assets are language-neutral Markdown and only command names/flags change (none planned).
  - Recovery: any phase stops on failed gate without rewriting canonical surfaces; the only external-state change is the cutover commit, reverted by `git revert` (tags kept for the last Go release).
- rejected_alternatives:
  - Strangler per-subsystem coexistence: two live binaries to maintain for months; rejected by owner (big-bang chosen).
  - Rust FFI sidecar keeping Go CLI: keeps Go forever; contradicts owner driver (own a Rust codebase).
  - `rmcp` official SDK: its model of the protocol fights the custom revisions (`server/discover`, per-request `_meta`, exact error-code semantics); hand-rolled serde_json is smaller and testable.
  - Turso/Limbo pure-Rust SQLite: not production-ready, FTS5 incomplete; rusqlite bundled matches the modernc engine bit-for-bit.
  - tokio: concurrency surface is 3 files; async adds runtime risk with zero payoff.
  - New separate repo: loses asset/history adjacency; in-repo `crates/` keeps one identity.

- 2026-09-04: Big-bang over strangler/hybrid; Go binary retained as living parity oracle until cutover.
- 2026-09-04: rusqlite bundled over Turso/Limbo (unproven FTS5); hand-rolled MCP JSON-RPC over rmcp (custom protocol revisions).

- 2026-09-04: No async runtime; concurrency surface (3 files) ports with std threads.
- 2026-09-04 (m0): Rust `create_dir_all` does not apply modes to intermediate directories (Go `MkdirAll` does); ported `ensure_directory_mode` as a walk-create-chmod over missing ancestors to preserve Go semantics — caught by the parity harness (wiki/ dir 0755 vs 0700).
- 2026-09-04 (m0): Parity manifest reports the coordination control path workspace-relative (`control_rel`); Go `GenerationPath` returns a canonicalized root while `RuntimeDir` is uncanonicalized, so a runtime-dir-relative field was ambiguous under /tmp symlinks.
- 2026-09-04 (m0): Generation-state parity via the exported Go API is deferred to m4 (read/write generation helpers are unexported and index-coupled); m0 covers generation semantics through Rust unit tests (round-trip, extra-fields, null, published-newer).
- 2026-09-04 (m0): Workspace crate version pinned 0.3.0; edition 2021; toolchain stable via rust-toolchain.toml.
- 2026-09-04 (m5-W1): Go JSON parse-error message text is unportable (serde's own text); codes and fatal-session behavior match Go exactly. Go dispatch is async (responses can reorder); Rust is sequential — no W1 test depends on reordering; flag for W2/MCP conformance re-check.
- 2026-09-04 (m1): include_dir embeds the full assets/ tree; extraction re-applies the go:embed pattern filter (view/ + embed.go excluded, dot/underscore exclusion, .go skip) — pinned by a layout-parity test against Go's documentedEmbeddedAssetPaths.
- 2026-09-04 (m2): yaml.v3 output is NOT reproducible by any libyaml-based emitter (4-space root indent, yaml.v3-specific quoting rules); serde_yml is parse-only and `yaml.rs` hand-rolls the emitter for the closed frontmatter schemas, oracle-verified by a committed 150-case scalar corpus + byte-identical claim fixtures + 3-way parity manifests. Any drift fails tests loudly instead of silently diverging.
- 2026-09-04 (m2): `sha2 = "0.10"` added beyond the ≤10-crate budget — SHA-256 is load-bearing everywhere; hand-rolling was rejected. Budget now 11 crates.
- 2026-09-04 (m2): `recoverPendingTransitionForMutationUnlocked` ships as a fail-closed stub (mutation errors while a transition journal exists); full recovery ports with m3 transition.go. No m2 test covers the journal-present path.
- 2026-09-04 (m3): transition journal layout is byte-compatible with Go's JSON encoding (serde field order + hand-rolled std-alphabet base64 for target bytes, no new crate); the pending-transition journal is exclusive via hard_link-fails-on-existing (os.Link semantics). m2's fail-closed stub is replaced by real recovery; write_draft/add_file/approve/revoke/migrate now recover the journal before mutating.
- 2026-09-04 (m3): Go emits nil slices as JSON null in manifests; Rust parity serializes empty `related_claim_ids` as null (null_if_empty) to keep lifecycle manifests byte-identical.

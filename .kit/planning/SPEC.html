Architecture

Knowledge Priority Order

P0 Axioms — Core facts, CANNOT contradict P1 Mental Models — Reusable frameworks P2 Projects — Books, courses, experiments P3 Decisions — Why X over Y

Higher priority wins on conflict. Missing knowledge → STOP, never guess.

Invariants

  • I-1 Immutable sources: raw.md and source.yaml cannot be modified after ingest
  • I-2 Workspace lock: workspace_at_ingest must match active workspace at every state transition
  • I-4 QA gate: Apply STOPS if P0/P1 questions are awaiting_external or deferred
  • I-5 Citation: Every verified-facts.md entry must cite question ID + wiki path
  • I-8 Resumable: checkpoint.json allows resume from any file if interrupted
  • I-9 Workspace-scoped search: qmd query MUST be scoped to active workspace collection

Retrieval Pipeline (/ask)

3-stage pipeline: parse keywords → qmd BM25 search → answer with context. No models needed.

1
wiki-planner — Parse Keywords
Parse user question → extract search keywords + identify domain
Input: User question string
Output: { workspace, keywords, domain }
Agent: wiki-planner (Sonnet, tools: Read, Glob, Grep)
Example: "How does SOLID relate to DI?" → { keywords: "SOLID dependency injection", domain: "software-engineering" }
2
wiki-qmd-selector — BM25 Search + Post-Filter
qmd BM25 search → classify by path → re-rank by priority → write current-task.md
Steps:
1. Validate active workspace collection exists in qmd
2. qmd search keywords --collection {workspace} --limit 20
3. Classify: /axioms/* → P0, /mental-models/* → P1, /projects/* → P2
4. Re-rank: P0 first, then P1, then P2 (keep BM25 score within tier)
5. Fetch full body for top results via qmd.get(docid)
6. Write top 6-8 results → current-task.md
3
Main Agent (Builder) — Answer
Read current-task.md → answer using retrieved context. If gaps → STOP.
Input: current-task.md (ranked docs + knowledge gaps)
Behavior: Answer using ONLY retrieved context. If knowledge gaps exist → report them, do NOT guess, do NOT borrow from other workspaces.

Learning Pipeline (/learn)

4-stage evidence pipeline: raw notes → verified knowledge. Every fact must be traceable.

1
Ingest — /learn <source>
Create sources/{id}/raw.md + source.yaml (immutable). Lock workspace_at_ingest.
Input: Paste text, file path, or URL
Output: evidence/sources/{id}/raw.md + source.yaml
Invariant I-1: raw.md and source.yaml cannot be modified after this point
2
Analyze — /learn --analyze {id}
Run 4 CORE prompts: summary, contradiction check, questions, knowledge gaps.
Outputs:
• 01-summary.md • 02-contradiction.md • 04-questions.md • 08-gaps.md
3
Q&A — /learn --qa {id}
Batch P0-P3 questions → human answers → verified-facts.md (must cite).
Gate (I-4): If P0/P1 questions are awaiting_external → pipeline STOPS
Invariant I-5: Every entry MUST cite question ID + affected wiki path
4
Apply — /learn --apply {id}
Update axioms/mental-models/projects. Write manifest + checkpoint. Auto-reindex qmd.
1. Read verified-facts.md
2. Update target wiki files
3. Write manifest.yaml + checkpoint.json
4. AUTO: trigger qmd index
5. State → applied

Key Decisions

✓D1: Simplified 3-Layer Model▼

Chosen: 3-stage retrieval + 4-stage evidence + workspace isolation

Rejected A: Full 5-stage wiki-template port — overkill

Rejected C: Flat wiki with tags — no isolation, knowledge bleed risk

Why: YAGNI — personal wiki doesn't need safety gates, but needs isolation + priority hierarchy

✓D2: qmd BM25 Search (no models)▼

Chosen: qmd search — SQLite FTS5, zero models

Rejected: Deterministic rules-based lookup (manual maintenance)

Rejected: qmd hybrid mode with 3 models (too complex, simple is the best)

Why: BM25 is good enough for personal wiki. 0 disk, 0 models, <1s latency. Upgrade later if needed.

✓D3: MCP Integration▼

Chosen: qmd MCP server (stdio mode)

Rejected: SDK (overhead per query), CLI via Bash (fragile parsing)

Why: Clean tool interface for Claude Code, matches subagent pattern

✓D4: Path-Prefix Post-Filter▼

Chosen: 1 collection per workspace, post-filter by path prefix

Rejected: 3 collections per workspace (N vs 3N config complexity)

Why: Simpler config, BM25 score still useful within each tier

✓D5: Node.js + TypeScript▼

Chosen: Node.js 22+ LTS, TypeScript 5.4+

Rejected: Python + Click (slower I/O), Go + Cobra (overkill)

Why: Fast dev, qmd native runtime, TypeScript type safety for state machine

✓D6: Personal Slash Command Naming▼

Chosen: /ask, /learn, /reflect, /workspace, /reindex

Rejected: /use-wiki, /evidence-ingest, /update-wiki

Why: Natural naming for daily personal use

Setup (First-Time)

# 1. Install Node.js 22+
nvm install 22 && nvm use 22

# 2. Install qmd
npm install -g @tobilu/qmd

# 3. Init zwiki
cd ~/Lab/zwiki && pnpm install

# 4. Generate qmd config
# engine/qmd-config.yml → ~/.config/qmd/zwiki.yml

# 5. Index (BM25 only — no models, no embed)
qmd --config-name zwiki index

# 6. Verify
qmd --config-name zwiki status
qmd --config-name zwiki search "test" --collection programming

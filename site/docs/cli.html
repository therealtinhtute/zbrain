CLI reference

zbrain - Go-native OKF trusted memory CLI

Usage:

zbrain <command> [arguments]
zbrain <command> --help

Use zbrain <command> --help for command-specific help. All examples below are the real shipped help output.

Workspace and evidence

  • setup

    Usage: zbrain setup
    Prepare the runtime directory and extract embedded assets.

  • workspace

    Usage:
    zbrain workspace create <name>
    zbrain workspace current
    Manage the active workspace.

  • evidence

    Usage: zbrain evidence add --file <path> --origin <uri-or-path> [--media-type <type>] [--workspace <name>]
    Options: --file <path> local source file to snapshot; --origin <uri-or-path> origin recorded in evidence metadata; --media-type <type> optional media type; --workspace <name> target workspace; defaults to the current workspace.

Claims and lifecycle

  • claim

    Usage:
    zbrain claim draft --tier <tier> --title <title> --basis <owner|evidence|derived> [--evidence <id>]... [--support <id>]... [--conflicts-with <id>]... [--workspace <name>]
    zbrain claim approve <id> [--workspace <name>]
    zbrain claim supersede <id> --tier <tier> --title <title> --basis <owner|evidence|derived> [--evidence <id>]... [--support <id>]... [--conflicts-with <id>]... [--workspace <name>]
    zbrain claim revoke <id> --reason <text> [--workspace <name>]
    Manage the four-state OKF claim lifecycle.

  • migrate

    Usage: zbrain migrate okf [--workspace <name>]
    Convert legacy zbrain claim files to OKF concepts.

Index and query

  • reindex

    Usage: zbrain reindex [--workspace <name>] [--embed]
    Rebuild the disposable workspace index. Option --embed: also compute and store loopback embedding vectors.

  • ask

    Usage: zbrain ask [--workspace <name>] [--include <name>]... [--embed] <query>
    Return trusted context JSON without calling an LLM. Options: --workspace <name> primary workspace; defaults to the current workspace; --include <name> explicit read-only secondary workspace, repeatable; --embed also use local embedding vectors; defaults to lexical-only.

Diagnostics

  • status

    Usage: zbrain status [--workspace <name>]
    status and doctor provide diagnostics for index and embedding configuration.

  • doctor

    Usage: zbrain doctor [--workspace <name>] [--probe-embedder]
    doctor reports domain findings with exit code 2; its JSON includes findings and next_action.

Gateway and viewer

  • mcp

    Usage: zbrain mcp serve
    Serve the trusted-agent MCP gateway over stdio.

  • mcp serve

    Usage: zbrain mcp serve
    Run the MCP stdio gateway. stdout is protocol-only; diagnostics go to stderr.

  • view

    Usage: zbrain view
    Serve the embedded read-only viewer over loopback (127.0.0.1). The viewer binds loopback only, sends strict CSP and nosniff headers, has no CORS, and returns 405 for every method other than GET and HEAD.

  • approval

    Usage:
    zbrain approval show <challenge-id>
    zbrain approval grant <challenge-id>
    Run the local owner-pinned approval ceremony for a lifecycle challenge.

  • approval show

    Usage: zbrain approval show <challenge-id>
    Print the challenge action summary as JSON.

  • approval grant

    Usage: zbrain approval grant <challenge-id>
    Confirm the last 16 hex characters of the action digest in an interactive TTY, then verify and print the one-time token as JSON for later apply.

See MCP gateway for how the gateway, approval ceremony, and viewer fit together.
